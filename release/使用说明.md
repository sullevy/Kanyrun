# Kanyrun 使用说明

## 目录内容
- `kanyrun`：主程序
- `kanyrun-ui`：菜单界面程序
- `config/config.toml`：默认规则配置
- `config/menu.ini`：默认 quickmenu 风格菜单
- `config/config.sample.toml`：可修改的配置样例
- `config/menu_sample.ini`：可修改的菜单样例
- `install.sh`：安装脚本
- `uninstall.sh`：卸载脚本
- `kanyrun-open.sh`：用于外部文件/目录选择后再弹菜单的通用脚本

## 安装
在 `release/` 目录下执行：

```sh
bash install.sh
```

安装后会写入这些位置：
- 程序：`~/.local/share/kanyrun/`
- 命令链接：`~/.local/bin/kanyrun`
- bundled 默认配置：`~/.local/share/kanyrun/config/`
- 用户配置：`~/.config/kanyrun/`
- 样例文件：`~/.local/share/kanyrun/samples/`
- 通用外部调用脚本：`~/.local/share/kanyrun/kanyrun-open.sh`

安装脚本默认会：
- 总是更新程序、bundled 默认配置、样例文件和说明文档
- 只在用户配置不存在时，才初始化 `~/.config/kanyrun/config.toml`
- 只在用户没有 `menu.ini` / `menu.conf` / `menu.toml` 时，才初始化 `~/.config/kanyrun/menu.ini`

这意味着你重复执行 `install.sh` 不会覆盖自己正在使用的菜单配置。

## 卸载
默认卸载程序和命令链接，但保留用户配置：

```sh
bash uninstall.sh
```

如果你还想同时删除 `~/.config/kanyrun/` 下的用户配置：

```sh
bash uninstall.sh --purge-config
```

## 运行
安装完成后可直接运行：

```sh
kanyrun
```

如果你还没有把 `~/.local/bin` 加入 `PATH`，也可以直接运行：

```sh
~/.local/share/kanyrun/kanyrun
```

## 常见用法
- `kanyrun`：直接弹默认 root 菜单
- `kanyrun --root-menu`：不读取选择区/剪贴板，直接弹默认 root 菜单
- `kanyrun --from-primary --menu`：读取 primary selection，但仍使用默认 root 菜单
- `kanyrun --text 'hello world'`：显式传入文本
- `kanyrun --text 'https://example.com'`：显式传入链接
- `kanyrun --files /path/a /path/b`：显式传入一个或多个文件/目录
- `kanyrun --menu --files /path/a`：强制对文件上下文弹菜单
- `kanyrun --test`：直接弹默认菜单做 UI 测试
- `kanyrun --menu-file ~/.config/kanyrun/menu-work.ini --test`：测试另一份菜单文件

查看帮助：

```sh
kanyrun --help
```

## 配置文件
Kanyrun 默认使用两份配置：
- `~/.config/kanyrun/config.toml`
- `~/.config/kanyrun/menu.ini`

其中：
- `config.toml` 管规则、provider、UI 开关、默认菜单文件
- `menu.ini` 管 quickmenu / RunAny 风格菜单结构

关键字段：

```toml
[ui]
show_icons = true

[menus]
default_file = "menu.ini"
default_id = "root"
fallback_id = "root"
```

- `show_icons = false` 可以隐藏菜单图标
- `default_file` 可以切到另一份 `menu.ini`
- `default_id` 默认用 `root`
- `fallback_id` 用于规则没命中，或命中的菜单因为后缀过滤后为空时的回退菜单

如果 `default_file` 指向的文件不存在，运行时会回退到 bundled 默认 `menu.ini`。

## menu.ini 语法
支持 quickmenu / RunAny 风格，但现在子项必须缩进：

```ini
*Google|@search:google
Copy text|@copy-text

-常用::common
    Documents|~/Documents

-Text file::@text-file|txt md rs
    *Kate|kate %f
    VS Code|code %f

-File::@file
    *Open|@open-file
    Show in folder|@reveal-file

-Directory::@directory
    *Open folder|@open-file

-Files::@file-list
    *Open parent folder|@open-directory
```

规则：
- `项目|命令`：普通菜单项
- `-子菜单::id`：一级子菜单
- `--子菜单::id`：二级子菜单
- `--`：分隔线
- `*项目|命令`：默认高亮项
- `; ...`：注释

补充说明：
- 子菜单里的项目必须缩进，4 个空格或 tab 都可以
- `::id` 用来声明稳定菜单 ID，便于和 `config.toml` 里的 `menu = "file"` 之类规则对应
- 非 `@` 项目都显示在默认 root 菜单里
- `::@id` 用来声明上下文默认类菜单；内部 ID 仍是 `id`，但默认 root 菜单里不会显示这个入口
- `--menu` 强制弹菜单时会优先选择上下文默认类：`file-list`、`directory`，或文件后缀命中的 `::@...|ext`；文本上下文使用默认 root 菜单
- 单文件没有命中后缀菜单时，会先找 `::@file` / `::file`，没有再回退到默认 root
- `-子菜单::@id|txt md rs` 这种写法会给上下文默认类加后缀过滤；只有当前文件上下文命中这些后缀时才会优先弹出
- 如果后缀过滤后的目标菜单为空，运行时会回退到 `[menus].fallback_id`

支持的内置动作：
- `@search:<provider>`
- `@copy-text`
- `@copy-path`
- `@open-file`
- `@open-directory`
- `@reveal-file`

支持的快捷命令推断：
- `https://...` 会当成 URL 动作
- `~/...`、`/...`、`./...`、`../...` 会当成路径动作
- 其他内容按 shell 命令处理

单个菜单项需要专属环境变量时，直接写成 shell 命令即可：

```ini
WPS|env QT_IM_MODULE=fcitx GTK_IM_MODULE=fcitx XMODIFIERS=@im=fcitx wps %f
qimgv|env QT_SCALE_FACTOR=1 qimgv %f
```

这种写法只影响当前菜单项，不会污染其他命令。`%f` 会作为单个 shell 参数安全传给应用，文件名里有空格也可以正常打开。

支持的占位符：
- `%s`：当前文本
- `%f`：当前文件路径
- `%A_YYYY%` `%A_MM%` `%A_DD%` `%A_Hour%` `%A_Min%` `%A_Sec%`
- `{text_preview}`：文本菜单里用于显示当前文本预览

可直接参考：
- `release/config/menu_sample.ini`
- `~/.local/share/kanyrun/samples/menu_sample.ini`

## 通用外部调用
`kanyrun-open.sh` 用于任何需要“外部选择文件/目录后，再触发 Kanyrun”的场景。

它支持两种模式：
- **有参数**：直接使用传入的文件和目录路径，也接受 `file:///...` URI
- **无参数**：快速尝试读取当前活动窗口的上下文
  1. 如果当前活动窗口是 Dolphin，只触发复制当前选中项并读取新鲜的 `text/uri-list`
  2. 如果当前活动窗口是 FSearch，只发送一次复制快捷键并解析新鲜文件路径
  3. 如果当前窗口没有新鲜文件/目录选择，回退执行 `kanyrun --menu --from-primary`；有文本 primary selection 时也显示默认 root 菜单

拿到路径后会：
- 过滤无效项
- 兼容引号、`file://localhost/...` 和 `file:///...`
- 归一化为绝对真实路径
- 自动去重
- 最终调用 `kanyrun --menu --files <path1> <path2> ...`

其中 Dolphin 的无参读取会短暂改写一次剪贴板，并在读取完成后尽量恢复原内容。

## 常驻模式
`kanyrun` 现在默认会优先连接常驻 daemon，以减少连续触发时的冷启动开销。

常用参数：

```sh
kanyrun --daemon-idle-timeout 300 --ui-idle-timeout 15
```

- `--daemon-idle-timeout <秒>`：daemon 多久无请求后退出
- `--ui-idle-timeout <秒>`：warm UI 子进程多久无请求后回收
- `--oneshot`：跳过 daemon，按旧模式单次启动

### KDE 快捷键建议
- 想直接弹默认菜单：绑定 `~/.local/bin/kanyrun`
- 想对当前复制/选中的文件或目录弹上下文菜单：绑定 `~/.local/share/kanyrun/kanyrun-open.sh`
  在 Dolphin 内从全局快捷键触发时，会优先尝试读取当前活动 Dolphin 窗口的选中项。

### 直接传参
如果某个外部工具本身就能传文件参数，也可以直接这样配置：

```sh
~/.local/share/kanyrun/kanyrun-open.sh /path/a /path/b
```

例如 Dolphin 外部工具可直接配置：

```sh
~/.local/share/kanyrun/kanyrun-open.sh %F
```

其中 `%F` 表示所选文件列表。

同时会导出这些环境变量：
- `KANYRUN_SELECTED_COUNT`
- `KANYRUN_SELECTED_PATHS`
- `KANYRUN_SELECTED_FIRST`
- `KANYRUN_SELECTED_DIR`
- `KANYRUN_SELECTED_NAME`
- `KANYRUN_SELECTED_STEMS`

## 上传 GitHub 前清理建议
源码仓库建议保留：
- `src/`、`assets/`、`ui/`、`scripts/`、`release/` 下的脚本、配置样例和说明文档
- `Cargo.toml`、`Cargo.lock`、安装/卸载脚本、项目说明文档

源码仓库建议排除：
- Rust 构建产物：`target/`
- Qt/CMake 本地构建产物：`.build/`、`ui/**/build/`、`ui/**/build-*/`
- 本地缓存和智能体状态：`.cache/`、`.agents/`、`.claude/`、`.codex/`
- 外部参考项目或个人工作目录：`refers/`、`Finance/`
- release 里的本机二进制：`release/kanyrun`、`release/kanyrun-ui`

当前仓库已提供 `.gitignore` 覆盖这些路径。发布二进制时建议用 GitHub Releases 上传打包产物，而不是直接提交到源码仓库。

## 重新打包
如果你在源码目录更新了代码，可直接重新生成并同步 `release/`：

```sh
bash scripts/build-release.sh
```

这个脚本现在会自动：
- 编译 Rust release 二进制
- 编译 Qt UI release 二进制
- 把最新产物同步进 `release/`
